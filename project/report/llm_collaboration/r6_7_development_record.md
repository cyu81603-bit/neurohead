# R6.7 并发交谈与上下文动作判断

此前回复生成要等动作判断，且程序会把部分模型回答替换成固定的动作回应。R6.7让两条路并发运行：聊天模型的原话交给语音，动作判断的登记ID交给现有动作库，各自就绪就消费，不互相等待。不向聊天模型注入本轮动作规划，不播报规划理由，也不在语音开始时重触发同一个动作。

聊天用系统提示约束自然交谈、话题变化、实际身体能力与视觉事实。程序不再用固定“抬头看看/眨一下”等句式改写回答。提示词能引导表达，但不能保证小型本地模型每次都不重复或永远理解正确。模型请求失败时保留明确错误提示，不把离线模板当成模型回答。

## 两路共享上下文

每轮开始前只捕获一次上下文快照，随后同时提交给聊天和动作判断。快照由短时记忆锁读取，不等待聊天网络调用的长锁。动作路得到最近对话、压缩摘要和单独记录的动作意图；聊天路只使用对话内容，不读取动作意图记录。模型刚生成的本轮回复不能反过来改变本轮动作请求。

动作路利用历史理解“再来一次”“刚才那个动作”。历史仅作背景；普通提问、引用、否定、取消不重放动作。没有唯一指代时返回空数组。意图记录明确标为未确认执行，不能当作实物动作证据。规划背景按上下文预算裁剪，清空对话会同时清除两类记忆。

本轮明确请求优先于历史：未指定侧别的wink仍是右眼，不能继承旧左眼拒绝；明确左眼请求不换成右眼，也不能自行添加微笑或摇头来表示拒绝。登记ID、会话许可、右眼许可签名和唯一控制器仍由原路径校验，没有关键词直接发PWM。

## 取消与运行边界

每轮有独立请求ID和取消代次。中断取消本轮已派发动作、停止语音并放弃迟到结果；正在进行的HTTP可能仍在服务端完成，但不再触发语音或动作，也不写回已取消轮次的记忆。一条路失败不阻断另一条。软件并发表示请求和消费独立，不代表已证明Ollama/GPU在同时计算两条请求。

主控仍使用R6.5/R6.6的动作版本6：追踪预留80μs抬头空间、CH6/7自动屏蔽、右眼wink签名、下颚1200/1300固定点和同学原三栏界面均保留。硬件位流、固件和眼球原motion_inhibited记录不修改。启动器以semantic_policy_revision=2区分新旧进程，拒绝同时创建两个控制器。

集成回归覆盖先完成先消费、互不阻塞、单路失败、中断及迟到结果、同一快照共享、上下文不等待聊天锁、取消记忆清除等。`scripts/check_action_context.py`、`check_wink_defaults.py`、`check_dialogue_context.py`、`check_parallel_dialogue.py`只调用本机模型，不播放音频、不派发动作。最终结果和部署状态以build/parallel_dialogue_r6_7_verification.json为准。
